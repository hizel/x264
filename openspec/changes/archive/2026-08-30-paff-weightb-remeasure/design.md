# Design: paff-weightb-remeasure

## Context

`paff-weightb` (archived) verified weighted biprediction under PAFF is
conformance-correct (28/28 B-field JM round-trips after fixing the
`int8_t` bipred_weight_buf overflow and the signed-byte-multiply
pixel_avg asm extrema) but killed it on quality: +0.272% BD-rate on a
single synthetic `xfade(testsrc2, smptehdbars)` clip, with the
progressive encode of the same clip also at ~0%.  The kill decision is
only as strong as that clip, and the clip never proved it exercises the
feature.  The existing stand lives in `tools/test_paff.sh`
(`make_dissolve_clip`, `cmd_weightb`, the `bdrate` helper); the force-off
lives in the `x264_encoder_open` validation block.

## Goals / Non-Goals

**Goals:**
- A re-measurement whose result is trustworthy in BOTH directions:
  a positive control that proves the content is weightb-sensitive, then
  the PAFF measurement on that same content.
- Realistic ffmpeg-generated dissolve/fade content (real scenes,
  crossfades, dips to black, film grain) — no new tooling dependencies.
- Pre-registered thresholds fixed in this document before any run.

**Non-Goals:**
- Enabling explicit weights (x264 only ever signals
  `weighted_bipred_idc = 2`, implicit; nothing to enable there).
- Touching progressive/MBAFF weightb behavior (upstream's business).
- Re-proving conformance from scratch (done in `paff-weightb`; only a
  regression re-run on the enable path).
- Speed measurements (the feature's cost is negligible; quality decides).

## Decisions

### D1: Clip set (all generated by ffmpeg lavfi/filters)

- **C1 real-scene crossfade** (primary): two DISTINCT real clips from
  env vars `PAFF_WB_SRC_A` / `PAFF_WB_SRC_B` (the external-clip pattern
  of `test_vbv_determinism.sh`), trimmed to 4 s each,
  `xfade=transition=fade:duration=1.5:offset=0.5`.  The blend zone sits
  at t=0.5..2.0 s so it dominates the coded window on BOTH ffmpeg
  lines: `tinterlace` merge doubles the height on ffmpeg 8, so 100
  coded frames cover only the first ~2 s of the timeline (an offset=2
  blend would fall entirely outside the window and encode pure scene
  A); on ffmpeg <= 7 the window covers ~4 s.  The generator verifies
  the blend is really inside the window (mid-window decoded frames
  match neither source).  Real texture + real motion + a 1.5 s blend
  zone: the content implicit bipred weights exist for.  Missing env
  vars -> cell skipped with a message (project pattern), the fallback
  is C3 alone and the conclusion is recorded as lavfi-only.  C1
  additionally runs at 720x576 (native interlace-broadcast geometry)
  alongside QCIF — see the geometry note below.
- **C2 dip-to-black** (diagnostic only): source A with `fade=t=out`
  then `fade=t=in` (1.5 s each).  Classic film fade.  The archived
  `paff-weightb` design classifies fades-to-black as weightp territory
  (implicit POC-distance weights do not track fade depth across the
  black plateau), so C2 is measured and published but is NOT a
  candidate for the stage-2 primary clip; a large C2 gain would
  challenge that classification and is investigated, not silently
  used — see Risks.
- **C3 grained synthetic crossfade**: the old `testsrc2`/`smptehdbars`
  xfade recipe plus `noise=alls=10:allf=t+u`.  Tests the hypothesis that
  the old clip was too clean to need weights.
- **C4 legacy synthetic crossfade**: the exact old clip, unmodified —
  reference cell that must reproduce the ~0.272% number (sanity that the
  stand still measures the same thing).
- **C5 non-dissolve control** (unconditional): source A straight, no
  fades — or, when `PAFF_WB_SRC_A` is unset, the lavfi control recipe
  (the existing `make_control_clip` pattern; neutrality does not
  require real footage).  C5 never skips, and the variant used is
  recorded in `results-stage1.md`.  weightb must be ~neutral here; a
  regression beyond ±0.5% vetoes the enable outcome (hard condition,
  see D2).

All clips 100 frames, yuv420p, 50 fps.  One `tinterlace`'d file per
clip: TFF cells encode it with `--paff --tff`, BFF cells re-encode the
SAME file with `--paff --bff` (no field-swapped file — swapped fields
are different pixels and would void the sign-agreement rule in D2);
the progressive control runs the pre-tinterlace stream — same pixels,
so progressive and PAFF numbers are comparable per clip.
Geometry: all cells run at the stand's 176x144 (QCIF) for strict
comparability with C4 and the archived numbers — QCIF geometry is an
accepted limitation of the re-measurement, recorded like the
synthetic-only limitation it replaces — plus one duplicate C1 cell at
720x576 to check the effect is not a QCIF artifact (sign-agreement
rule in D2).

### D2: Two-stage protocol with pre-registered thresholds

Stage 1 — positive control (progressive): CRF 18/23/28/33, `--threads 1`,
weightb on vs off, BD-rate PSNR-Y (existing `bdrate` helper) per clip.
Gate: at least one clip shows progressive gain >= 1.0%.  No such clip ->
KILL confirmed on all tested content including progressive; record and
stop (the PAFF question is moot).

Stage 2 — PAFF: the same sweep under `--paff`, TFF and BFF, on all
clips (C1 at both geometries).
The weightb-on rows require locally reverting the validation force-off
(the stand already warns when the force-off eats `--weightb`; the revert
hunk is documented in tasks and never committed on the kill path).
Primary metric: BD-rate on the clip with the largest stage-1 gain,
chosen among the crossfade clips C1/C3/C4 only (C2 is diagnostic, C5
is the veto control — neither is eligible).
Decision: primary gain >= 1.0% AND |C5| <= 0.5% -> ENABLE;
primary gain <= 0.5% -> KILL; in between -> one extended sweep
(CRF 15/20/25/30/35, 200 frames): extended gain >= 1.0% -> ENABLE,
otherwise KILL.
BFF must agree in sign with TFF; a sign flip is investigated, not
averaged away.
Geometry divergence rule: C1 at 720x576 must agree in sign with C1 at
QCIF.  A disagreement is not averaged: if 576i shows a >= 1.0% gain
while QCIF shows ~0, decide by 576i (QCIF is the insensitive geometry
for this content); the reverse means the QCIF gain was noise and the
verdict is KILL by the primary cell.  Either case is recorded in
`results-stage2.md`.

Divergence rule: if stage 1 passes but PAFF shows ~0% or negative while
progressive gained on the SAME pixels, that is a suspected bug in the
field weight path (list expansion can put both bipred references on the
same POC side — the exact corner the two `paff-weightb` asm fixes came
from), not evidence against the feature.  Investigate before deciding;
KILL on quality grounds requires the field path to be verified correct
first (spot-check weights against `bipred_weight_buf` per the archived
design's debug procedure).

### D3: Enable path (only on ENABLE)

First re-apply the **conformance fix bundle**: the two latent-bug fixes
that `paff-weightb` landed and then reverted with the kill, because the
force-off makes them unreachable — the `int8_t bipred_weight_buf`
widening (it cannot hold the boundary weight 128) and the
signed-byte-multiply `pixel_avg` asm extrema (-64/128: x86
SSSE3/AVX2/AVX-512, LoongArch LSX/LASX).  The bundle is verified by
`checkasm8` on every arch touched and by the instrumented
gate-sensitivity proof (a temporary build with a debug counter in
`x264_macroblock_bipred_init_paff`, as in the archived change) showing
the matrix exercises weights != 32 including the [-64, 128]
neighbourhood.  Only then: remove the force-off warning-and-disable in
`x264_encoder_open`; re-run the full B-field JM conformance matrix with
weightb on (regression re-check — the tree moved since `paff-weightb`);
finalize the delta spec with the ENABLE variant; rewrite the
weighted-biprediction paragraph in `doc/paff.txt` with the numbers;
update the `weightb` glossary entry in CONTEXT.md in the same commit as
the verdict.

### D4: Kill path (otherwise)

Force-off stays; `doc/paff.txt` gains the real-content numbers and the
positive-control result as the definitive rationale; the `weightb`
glossary entry in CONTEXT.md is updated with the new rationale in the
same commit as the verdict (it currently cites the synthetic-dissolve
number this change re-measures); the delta spec is finalized with the
KILL variant; the new generators and the `weightb2` command stay in
`tools/test_paff.sh` so the measurement is reproducible.

## Risks / Trade-offs

- [No real clips available (env vars unset) -> C1/C2 skip, conclusion
  rests on lavfi-only content] → the fallback is recorded with the
  numbers, and the ENABLE outcome additionally requires the grained
  synthetic (C3) to pass, since grain is the realism lever available
  without external footage.  C5 never skips: it falls back to the lavfi
  control recipe, so the enable veto always runs.
- [C2 shows the largest stage-1 gain despite being weightp territory by
  the archived design's classification] → C2 is diagnostic and not
  eligible as the primary; a large C2 gain challenges the archived
  classification and is investigated before any verdict, not silently
  used.
- [BD-rate numbers are ffmpeg-version-dependent: `tinterlace` merge
  doubles the height on ffmpeg 8, changing the blend fraction inside
  the coded window vs ffmpeg <= 7] → the ffmpeg version is recorded in
  `results-stage1.md`, and C4 must reproduce the archived ~0.272% on
  the same ffmpeg line before any other number is trusted.
- [BD-rate noise on 100-frame clips flips a borderline result] →
  thresholds are wide (0.5/1.0) and the middle band defaults to KILL;
  the extended sweep exists for borderline cases.
- [The stage-2 weightb-on rows silently encode weightb-off because the
  force-off was not reverted] → the stand already prints the warning;
  tasks assert its ABSENCE in the on-rows' logs before accepting numbers.
- [Enabling churns RD decisions on all B-field content] → that is the
  cost the 1.0% threshold prices in; below it the churn is not worth it.
